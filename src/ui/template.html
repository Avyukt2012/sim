The four sensor rules

The two IR sensors sit just outside the two edges of the black tape. When the robot is centred, both see white. Each sensor only says “black” or “white”, so there are only four possible readings:

LeftRightMeaningWhat LF3 does
whitewhiteline between the sensorsstraight (SPEED_STRAIGHT)
BLACKwhiterobot drifted rightturn left
whiteBLACKrobot drifted leftturn right
BLACKBLACKcrossing linestraight on, a bit slower

Gentle first, then sharp

A turn starts gentle: the outer wheel drives at TURN_OUTER and the inner wheel stops (TURN_INNER_SOFT = 0), so the robot swings round its inner wheel.

If the same sensor is still on black after SHARP_AFTER_MS (30 ms), the bend must be sharp. Now the inner wheel runs backwards (TURN_INNER_SHARP) and the robot spins almost on the spot. Watch the trail turn from amber to red-orange in tight curves.

Line memory

At the 90° corner the robot can overshoot so far that both sensors end up on white, which normally means “go straight”. So after a sharp turn LF3 remembers which way it was turning. If it then sees no line for LOST_AFTER_MS (250 ms), it spins back that way until one sensor finds the tape again (magenta trail, “?” marker). After SEARCH_GIVE_UP_MS (2 s) without the line it stops.

Both sensors black during a sharp turn is treated as being on top of the corner, not as a crossing.

What the simulator models

Each wheel follows its target speed with a delay (TAU), PWM below DEAD does not move it, and the robot steers by the speed difference of its two wheels. The program runs every 0.5 ms, exactly as in the C++ reference simulator. The 5 cm gap needs no special rule: both sensors see white, so the robot drives straight across it.

What it does not model: wheel slip, battery sag, sensor noise or sensor height. Treat the numbers as a comparison between settings, then confirm on the real track.
